# AgentHome 调研总览：GPUI / GPUI Kit 为什么火，以及我们要借什么

> 日期：2026-11-05。本文是四份原始调研（`docs/research/01~04`）的提炼版，只保留结论与对本项目有用的部分。所有数字均为 2026-11-05 用 `gh api` / crates.io API 实测，来源见各原始报告。

---

## 0. 先澄清名字

用户口中的 "gptui / gptui kit" 经核实指的是：

| 口语 | 实际项目 | 说明 |
|---|---|---|
| gptui | **GPUI** | Zed 编辑器团队的 Rust GPU 加速 UI 框架（`zed-industries/zed` 的 `crates/gpui`，crates.io 上的 `gpui`） |
| gptui kit | **GPUI Kit**（原 gpui-component） | Longbridge（长桥证券）开源的 GPUI 组件库，2026-09-03 随 v0.6.0 从 `longbridge/gpui-component` 改名为 `longbridge/gpui-kit`，文档站 gpui-kit.com |

同名干扰项：`happyapplehorse/gptui` 是一个 Python 终端 ChatGPT 客户端，热度很低；`iamnbutler/gpuikit`（199 star）是另一个 SwiftUI 风格的小项目，与 Longbridge 无关。后文一律指 GPUI 与 GPUI Kit。

## 1. 它们是什么

### 1.1 GPUI

- 官方定位："fast, hybrid immediate and retained mode, GPU-accelerated UI framework for Rust"，Apache-2.0。
- 是 Zed（92,739 star，2026-04-29 发布 1.0，日活数十万开发者）和 Zed 新产品 Delta 的 UI 底座。
- 核心架构：
  - **Entity / View / Element 三层**：`App` 集中持有所有状态，`Entity<T>` 只是类型化句柄，读写必须经 `Context<T>`，通过 `notify / observe / emit / subscribe` 驱动重绘。这套所有权模型是它和 egui（即时模式）、iced（Elm 架构）最大的差异。
  - **Tailwind 风格的 styled builder API**（`div().flex().gap_2().bg(...)`）+ Taffy flexbox/grid 布局。
  - **自绘到底**：macOS Metal + CoreText，Windows D3D11 + DirectWrite，Linux 2026-02 起 wgpu + cosmic-text，Web 走 wgpu → WebGPU/WebGL2。不用任何 OS 控件，字形光栅化自己管。
  - 自带异步执行器（`background_executor` / `Task`）、Action + Keymap + Focus 分发系统，2026 年才补上 AccessKit 无障碍骨架。
- 版本现状（最大的坑）：crates.io 官方 `gpui` 停在 **0.2.2（2025-10-22）**，落后 main 超过 12 个月；main 已拆成 gpui / gpui_platform / gpui_web / gpui_macros 等 13 个 crate，一个都没发。社区用 Longbridge 的 **`gpui-pre` 周快照** 顶上（38 万下载），另有 `gpui-ce`、`gpui-fast` 等至少 6 条发行谱系，**不能混用**。

### 1.2 GPUI Kit

- 19,185 star（创建于 2024-06），最新 v0.9.0（2026-11-02），**几乎每周一版**，minor 约 3 周一次且常带 breaking。
- 三层结构（v0.6.0 起）：`gpui-kit` 门面 → `gpui-component`（shadcn 风格样式层）→ `gpui-base`（无样式行为层）；可选 `gpui-shell`（内嵌 JS 运行时）、`gpui-webview`、`gpui-fps`。官方类比：GPUI ≈ HTML + Tailwind，gpui-base ≈ Base UI，gpui-component ≈ shadcn。
- 75+ 组件：DataTable / VirtualList（宣称几十万行）、7 种图表（含 Sankey）、TextView（原生 Markdown/HTML + 流式渲染）、Message / Bubble / MessageScroller、Dock 可序列化布局、Diff、带 Tree-sitter + LSP 的代码编辑器、Settings、Command(⌘K)。
- 主题：`theme.json` + shadcn 语义 token，38 个预设（含 macOS Classic），`ThemeRegistry::watch_dir` 热加载。
- 接入方式：`gpui-kit = "=0.9.0"`，GPUI 版本由 kit 锁定（当前 `gpui-pre =0.3.11`），**不要再自己直接依赖 gpui**。

## 2. 为什么 2025Q4 到 2026 年爆火

按证据排序，六个推力：

1. **Zed 的成功是母体。** Agent Panel（2025-05）→ ACP 协议（2025-08）→ Claude Code / Codex / Gemini CLI 接入 → Sequoia 3200 万美元 B 轮 → Windows 稳定版（2025-10）→ 1.0（2026-04）→ Delta（2026-08）。Zed 成为"AI 时代 VS Code 替代品"叙事的主角，"Zed 用什么画 UI"随之被反复提及。
2. **GPUI Kit 补上了"零组件"这个最大短板。** GPUI 自身连 Input 都没泛化。Longbridge 用它重写了 Electron 版 Longbridge Pro（券商桌面端）后沉淀出组件库。2025-10-27 HN "Rust cross-platform GPUI components" **515 分 / 218 评论**是热度拐点；2026-09 改名 GPUI Kit 并发 `gpui-pre` 快照解决了"crates.io 版本太旧"的痛点。2026-10-01 到 11-05 五周涨约 3,800 star（约 110/天），是整个 Rust GUI 生态最陡的曲线。
3. **coding-agent 原生客户端热潮。** awesome-gpui 收录 124 个应用，开发者工具分类里一大批是 agent 相关：Ghostex、sheprd、Waku、Zeron、Paneflow、Wake、oxideterm 等。原因很具体：agent 界面要持续流式 token、60 到 120 fps 重绘终端网格、绝不能丢按键、需要原始 key chord 和干净的 IME / 焦点控制。Tauri 的 webview 要 JS 往返，Electron 太重。Paneflow 作者先用 Tauri 做了一版又放弃。这批开发者是 Claude Code / Codex 重度用户，和 Zed 用户群高度重叠。
4. **"去 Electron 化"叙事。** Zed 1.0 博客直接把 Atom/Electron 的性能天花板作为创立理由；Longbridge 宣传比 Electron 少 60% 到 80% 内存（厂商声明，未核实）；Shopify CEO Tobi Lütke 用 GPUI 写 disktree（3,989 star）并公开宣传，是典型名人效应。
5. **wgpu 化与 Web 化降低了"只为 Zed 服务"的疑虑。** 2026-02 Linux 改走 wgpu，gpui_web 进 main，出现 gpuix（React 绑定，2,867 star）、React Native GPUI、gpui-mobile 等"把 GPUI 当平台"的项目。
6. **争议本身制造曝光。** 2025-12 的 gpui-ce fork、2026-02 Zed 维护者 Discord "major brakes" 言论、2026-08 的 "what happened to gpui?"、2026-10 的 "The Electron Killer That Never Left Home" 质疑文，每一条都在 HN / Reddit 引发数百评论。实测 crates/gpui 两个月 100 多次提交，开发并没停，只是不再为外部用户发版。

## 3. 独特性（相对竞品）

| 维度 | GPUI + GPUI Kit | Tauri | egui | iced | Slint | Electron |
|---|---|---|---|---|---|---|
| star | 92.7k / 19.2k | 112k | 32k | 31.9k | 24.4k | — |
| 渲染 | GPU 自绘，拥有整条字形链路 | 系统 WebView | GPU 即时模式 | GPU 保留模式 | 自绘或 Qt 后端 | Chromium |
| 性能上限 | 最高（120fps、输入零往返） | 受 WebView 限制 | 高但 CPU 侧重 | 高 | 高 | 低 |
| 组件数 | 75+ | HTML 生态无限 | 16 个 widget | 35 个 widget | 中 | 无限 |
| Markdown / 代码编辑 | 原生，含流式与 LSP | 靠前端库 | 弱 | Markdown 不支持内联 HTML | 无 | 靠前端库 |
| 中文/IME | 基础可用，边角 bug 多 | 好 | 需自带字体 | 一般 | 一般 | 好 |
| 无障碍 | 刚起步 | 好 | 弱 | 一般 | 好 | 好 |
| API 稳定性 | 最差，周级 breaking | 稳 | 稳 | 稳 | 稳 | 稳 |
| 文档 | 最薄 | 好 | 好 | 好 | 好 | 好 |
| 产物体积 | 15 到 40 MB | 5 到 15 MB | 5 到 10 MB | 5 到 15 MB | 5 到 15 MB | 80 到 150 MB |
| 治理 | 完全由 Zed 商业优先级决定 | 基金会 | 个人+社区 | 社区 | 公司 | OpenJS |

一句话：**GPUI 是 Rust 生态里性能上限最高、生产验证最强的 GUI 框架，同时也是 API 最不稳定、文档最薄、和单一产品绑定最深的框架。** 适合"工具型、重交互、开发者自用"的桌面应用，不适合需要快速上线或合规无障碍的产品。

## 4. 风险清单（要带进设计里的）

1. 版本锁定：锁 `gpui-kit = "=0.9.0"` 并提交 Cargo.lock；每 3 到 4 周跟一次 minor，读 release note 的 Breaking 段。
2. 首次编译 5 到 15 分钟，约 1,000 个依赖；debug 构建要调 `opt-level`。
3. Windows 最弱（TitleBar、Tab 缩进、VSync 等 open issue），Linux 需 Vulkan 驱动；生态普遍"macOS first，Win/Linux 标 beta"。
4. 中文 IME：Zed 仓库 2026-08 到 10 月新开 5 条 IME issue，GPUI Kit 的 macOS 拼音候选框残留 #3605 仍 open。中文用户产品必须自测输入。
5. AI Elements（Reasoning / Tool / Plan / PromptInput，对标 shadcn AI Elements）PR #3636 尚未合并，会话 UI 要部分自绘。
6. Chart 没有独立 Legend、没有热力图，需用 Plot 原语自绘。
7. 许可证：GPUI Kit 仓库 license 字段为 NOASSERTION（自定义 LICENSE 文件），使用前读一遍。
8. 治理风险：Zed 若弃用 GPUI 整个生态都悬；缓解因素是 Zed 刚融资并发 1.0 / Delta，Longbridge Pro 商业上依赖 gpui-kit。

## 5. 我们要借什么（选取优秀之处）

### 5.1 从 GPUI / GPUI Kit 本身

| 借什么 | 怎么用在 AgentHome |
|---|---|
| Entity / Context 状态模型 | 数据层（SQLite 查询、文件监听）跑在 `background_executor`，结果写回 Entity 后 `cx.notify()`；UI 不直接碰 IO |
| `theme.json` + `ThemeRegistry::watch_dir` | 直接复用，默认 macOS Classic，用户丢一个 json 进目录即可换肤 |
| `examples/tig`（Sidebar + Diff + Resizable 三栏骨架） | 归档浏览器的基础布局：左项目树 / 中会话列表 / 右对话详情 |
| `examples/stream-markdown` + TextView | 渲染助手回复、工具输出；流式能力留给未来"实时跟随正在进行的会话" |
| `examples/system_monitor`（实时图表） | 用量仪表盘的折线 / 面积图 |
| Sankey 图 | "项目 → 模型 → 成本"流向，这是别的仪表盘没有的视角 |
| DataTable / VirtualList | 几万条会话的列表与按 token / 成本排序 |
| Diff 组件 | 展示工具调用改了哪些文件 |
| Command(⌘K) + SearchableList | 全文搜索入口 |
| Settings 组件 | 设置页自带搜索 |
| #3636 AI Elements 的设计原则 | 受控 `RenderOnce` 值、统一 Trace 折叠行（Reasoning / Tool / Plan 共享几何与键盘路径）、状态用"图标 + 文字"不只靠颜色。未合并也照此自绘 |
| Dock 可序列化布局 | 第二阶段再用，MVP 用 Sidebar + Resizable 够了 |

### 5.2 从生态同类应用

| 项目 | 借什么 |
|---|---|
| **Wake**（1,532 star，会话归档浏览器） | 只读扫描各 agent 目录 → rusqlite 索引（可随时重建，star / pin 单独持久化）→ notify 增量更新；提供 MCP + CLI 让 agent 反查自己的历史；Insights 页（活动热力图、连续天数、周趋势、Top 模型）。这是最接近我们的参考实现，但它**不做持久拷贝**，30 天清理后数据照样没了 |
| **TokenMonitor**（用量仪表盘） | 同一数据层双前端：GPUI 桌面版 + ratatui TUI；单文件 musl 静态包 |
| **Waku / Zeron** | daemon 持 SQLite 与文件系统，GUI 只持展示状态；便于远程主机、崩溃恢复、自更新时替换 GUI |
| **Zedis** | 发布矩阵：同一 tag 出 dmg / AppImage / deb / rpm / tar.gz + `-fast` 变体 + SHA256SUMS + latest.json |
| **ccusage**（19k star，已重写为 Rust） | 按 `message.id + requestId` 去重、LiteLLM 定价表、5 小时滑窗估算 |
| **CodexBar**（23k star，菜单栏） | 菜单栏常驻形态、多 provider 额度卡片；教训是 Keychain 访问失败要静默跳过而不是反复弹窗 |
| **SpecStory** | 唯一做"持久拷贝"的竞品（但只覆盖 IDE 侧，且 Markdown 有损）。验证了"对抗自动清理的归档"是真实需求 |
| **txcript / lore-cli / Claudescope** | Rust 解析器源码与 `docs/formats/*.md` 格式逆向文档，直接作为我们 Provider 的字段参考 |

### 5.3 差异化定位（竞品都没做的）

- 几乎所有同类工具都是"原地只读 + 内存索引"，**没有一个解决 Claude Code 30 天 / Gemini CLI 30 天自动删除的问题**。
- 没有一个把"剩余额度"和"历史消耗"和"对话归档"放进同一个产品。
- 没有一个把采集入口做成可插拔的 Provider 协议让社区扩展。

这三点就是 AgentHome 的立足点。详见 `docs/01-产品与架构方案.md`。

## 6. 结论与选型

- **技术栈：Rust + GPUI Kit（crates.io 方式，锁 =0.9.0）+ rusqlite(bundled) + notify + tokio。** 已有 Wake、TokenMonitor 两个开源项目验证了同一路线。
- **平台策略：macOS 优先，Windows / Linux 从第一天起 CI 构建但标 beta。**
- **它是实验性项目，GPUI 的不稳定是可接受的代价**，前提是把版本锁死、把数据层与 UI 层切开，保证哪天换 UI 框架时数据层不动。
