# 13 · 来源插件开发指南（2026-11-10）

AgentHome 支持哪些 agent，全部登记在一张来源注册表里：`crates/core/src/providers/registry.rs`。同步引擎、命令行、仪表盘、归档都遍历这张表，不再各自写死来源列表。要支持一个新 agent（比如 OpenCode），写一个解析文件、登记一行、配一份测试，然后提 PR 即可。

> 现阶段只有**内置**来源：新来源要编进程序，通过 PR 贡献。不重新编译就能加的外部插件（已拍板的「JSON-RPC over stdio」协议）是下一步，见 `docs/01-产品与架构方案.md` 第 8 节决策 6。

## 1. 一个来源要实现什么

实现 `SourceProvider` trait（`crates/core/src/providers/mod.rs`），核心只有两件事：

| 方法 | 作用 |
|---|---|
| `id()` | 来源 id，对应 `ProviderId` 的一个变体 |
| `detect()` | 本机有没有这个 agent 的数据目录 |
| `root()` | 数据根目录（raw 层用原件相对它的路径作归档 key） |
| `discover()` | 列出全部会话文件 |
| `parse_file(path)` | 把一个会话文件解析成 `Session` + `Vec<Message>`，附警告与「跳过了什么」的计数 |

以下方法都有默认实现，按需覆盖：

| 方法 | 默认 | 什么时候覆盖 |
|---|---|---|
| `accepts(path)` | `None`（判断不了，变化时整个来源重新 discover） | 能判断「这个路径是不是会话文件」就实现，文件监听会快很多 |
| `watch_suffixes()` | `[".jsonl"]` | 会话文件不是 jsonl（如 Antigravity CLI 的 `.db`） |
| `watch_roots()` | 只有 `root()` | 有多个目录（如 Codex 的 `archived_sessions`） |
| `source_root(path)` | `root()` 包含它就返回 | 多个根目录时 |
| `line_parser(path)` | `None`（只能整文件解析） | jsonl 这类只追加的文件，实现后可按字节偏移增量入库 |
| `archive_raw(path)` | `true` | 原件会被整份改写、按版本归档只会无限增长时（SQLite、加密 `.pb`） |

## 2. 入库口径（必须遵守，否则统计串台）

- **token 统一成「新鲜输入」口径**：`input_tokens` 不含缓存读，缓存读放 `cache_read_tokens`，`input_includes_cache = false`。来源给的 input 若含缓存，解析时先扣掉。
- **推理 / 思考 token 计入 `output_tokens`**，同时在 `reasoning_tokens` 里记一份（思考按输出价计费）。不要两边都加。
- **usage 挂在每次模型调用的那条 assistant 消息上**，`requests = 1`。会话级 usage 是消息之和。成本用 `pricing::estimate_messages(&messages)`，不要对聚合后的 usage 估价（长上下文分档按单次请求判断）。
- **id**：`Session.id` 用 `<来源 id>:<machine_id>:<原生 id>`，消息 id 在会话内唯一即可。
- **不丢数据**：解析不了的行、缺字段写进 `warnings`；不入库的记录类型按类型计数写进 `ignored_records`。静默跳过等于数据悄悄变少。
- **只读**：绝不修改 agent 的原目录。SQLite 用 `SQLITE_OPEN_READ_ONLY` 打开。
- **不读凭据**：任何 token、OAuth 文件都不要碰（见 CLAUDE.md 已拍板决策 3）。

更完整的口径对照与业界做法见 `docs/12-成本口径核对.md`。

## 3. 加一个来源的步骤

1. 在 `crates/core/src/model.rs` 的 `ProviderId` 里加一个变体，并在 `as_str()` / `parse()` 里加上存库字符串。**这个字符串一旦发布就不要改**，库里的会话靠它归属。
2. 新建 `crates/core/src/providers/<名字>.rs`，实现 `SourceProvider`，并在 `providers/mod.rs` 里 `pub mod`。
3. 如有默认目录，在 `crates/core/src/paths.rs` 加一个函数。
4. 在 `registry.rs` 的 `builtin()` 里登记一行：

   ```rust
   ProviderSpec {
       id: ProviderId::OpenCode,
       name: "OpenCode",                     // 界面里的名字
       resident: None,                       // 栖息地里归哪位住户；None 照常入库，只是不画
       resume_command: Some("opencode --session {id}"), // 「继续」按钮复制的命令，没有就 None
       default_root: paths::opencode_dir,
       build: |root| Box::new(OpenCodeProvider::new(root)),
   },
   ```

5. 写测试（见第 4 节），跑 `cargo fmt --all --check && cargo clippy --workspace --all-targets -- -D warnings && cargo test --workspace`。
6. 用真实数据核对：`agenthome scan --db /tmp/x.db --no-raw` 扫进临时库，拿 agent 自己报的用量（如 `--output-format json` 的输出、官方 usage 页面）逐条比对 token。

没有住户的来源（`resident: None`）在归档、搜索、统计里正常出现，用注册表里的名字和中性色、机器人图标显示；栖息地仍是三位住户。

## 4. 测试怎么写

不要把真实会话文件提交进仓库（仓库公开，里面有你的项目名、路径，可能还有厂商的系统提示词）。照 `crates/core/src/providers/antigravity_cli.rs` 末尾的测试：

- 在测试里**手搓**一份最小 fixture，结构照真实数据，数字取自真实数据里 agent 自己报的用量。
- 断言「为什么重要」，而不只是「解析出来是什么」：缓存读有没有从输入里扣、思考有没有重复计、工具结果能不能挂回调用、不认的记录有没有被计数。
- 再测 `accepts` / `discover` 不认锁文件、临时文件、旧副本。

注册表自己的测试（`registry.rs`）会检查：id 不重复、解析器返回的 id 与登记一致、存库字符串能读回。

## 5. 参考实现

| 来源 | 文件 | 特点 |
|---|---|---|
| Claude Code | `claude_code.rs` | jsonl，流式多行同一条消息按 `message.id` 合并，按字节偏移增量 |
| Codex | `codex.rs` | jsonl / jsonl.zst，两个根目录，累计值求差 |
| Gemini CLI | `gemini.rs` | json / jsonl，按官方规则回放 `$set` / `$rewindTo` |
| Antigravity CLI | `antigravity_cli.rs` | 每个对话一个 SQLite，内容是无 schema 的 protobuf（`proto.rs` 按字段号读取），字段号对照 `agy -p --output-format stream-json` 逆推 |
