# 开发踩坑记录

> 2026-11-08 汇总。按领域分组，每条写「现象 → 原因 → 现在的做法」。构建与发布相关的坑见 `docs/08-构建与发布流程.md`。新坑追加到对应小节末尾。

## 1. GPUI / GPUI Kit

- **版本谱系混用会报 E0277。** crates.io 官方 `gpui` 停在 0.2.2；GPUI Kit 0.9.0 锁的是 Longbridge 的周快照 `gpui-pre =0.3.11`。只依赖 `gpui-kit = "=0.9.0"`（精确锁定），**不要再直接写 gpui 依赖**，GPUI 通过 `use gpui_kit::*;` 使用。升级前读 release note 的 Breaking 段，minor 版常有破坏性改动。
- **不要凭记忆写 API。** 源码克隆在 `~/code_hub/_ref/gpui-kit/`（v0.9.0），先 grep 签名；`skills/gpui-kit/references/coding-guides.md` 是规范。GPUI 本体源码在 `~/.cargo/registry/src/*/gpui-pre-0.3.11/`。
- `font_medium()` 等在 `gpui_kit::component::StyledExt`，不在 gpui 的 `Styled`，要单独导入。
- 主题 JSON：`highlight` 必须带 `"syntax": {}`，否则解析 panic；链接色用 `link / link.hover / link.active`；不要设 `font.family`（显式 family 不回退，本机没装 IBM Plex 就会乱）。
- **明暗主题不会自动跟随系统。** 需要启动时 `Theme::sync_system_appearance(None, cx)`，并在开窗回调里 `window.observe_window_appearance(...)` 再同步一次。调试用 `--appearance light|dark` 固定。
- gpui 没有旋转、单轴缩放、CSS 滤镜、径向渐变。栖息地动画的替代：摇头 → 左右平移，呼吸 → 整体高度变化，去饱和 → 降透明度，灯光 → 半透明圆 + 步进缓动。
- `uniform_list` 要求等高行：分组标题也得占一整行。变高列表用 `MessageScroller`（默认跟随尾部，要从头读需 `reset` 后 `scroll_to_item(0)`）。
- `Sidebar` / `SidebarMenuItem` 的选中态是整块填充，和设计稿的「琥珀字 + 左侧竖条」不符，左栏导航沿用自写的 `side_item`。
- 标题栏里要让某元素按整个窗口居中，得用绝对定位叠层并向左扩出红绿灯内边距；后来导航移到了左栏，标题栏只放页名、状态与搜索。
- 动画 id 用 `(ElementId, 状态 slug)`，换状态即重播；循环用 `.repeat()`。
- 首次编译 GPUI 约 3 分钟（debug）/ 1.5 分钟（release），debug profile 已设 `opt-level = 1`，依赖 `opt-level = 2`。

- **去掉标题栏后要自己负责拖窗口。** 窗口仍用 `TitleBar::window_options()`（透明标题栏、`app_owns_titlebar_drag: true`），AppKit 不会替你拖。可拖区域照 gpui-kit TitleBar 的写法：按下记一个标志、首次移动时 `window.start_window_move()`，双击 `window.titlebar_double_click()`（`on_double_click` 来自 `gpui_kit::component::InteractiveElementExt`）。红绿灯位置用 `TitlebarOptions.traffic_light_position` 调到与左栏顶行垂直居中。
- 不要把同一份栖息地在一屏里画两遍（左栏 + 仪表盘），用户会觉得冲突；栖息地只留左栏一份。

- **全局筛选控件必须让首屏有可见变化**，否则用户会认为它坏了。仪表盘曾有页头「今天 / 30 天 / 90 天 / 全部」，实际只影响首屏以下的卡片，且「今天」「全部」都退化成 30 天。规则：筛选放在它所控制的卡片上；跨卡联动要在被联动卡片的副标题写明。

## 2. 数据解析（core）

- **Claude Code 的 uuid 并不唯一。** fork / resume 会把历史行复制进新文件，resume 还会在同一文件里重写一段历史。messages 主键用 `(session_id, id)`，同文件按 uuid 去重，先到者为准，重复计入 `ignored_records["duplicate-uuid"]`。
- **子代理 agentId 跨父会话重复**（父会话 fork 时子代理文件一起被复制）：子代理 `native_id = "<父uuid>/<agentId>"`。
- 同一次 API 响应会拆成多条 assistant 行（共享 `message.id`），usage 只能算一次。
- Claude 记录类型远多于文档（本机 24 种 type，如 `atis-latch`、`frame-link`、`bridge-session`）。不认识的全部计数进 Report，不静默丢。
- **Codex 的 `input_tokens` 含缓存读**，和 Claude 口径不同，直接相加会让「输入」虚高两个数量级。入库前减去 `cached_input_tokens`，统一成「新鲜输入」，`input_includes_cache = false`。
- Codex 冷文件会被 Codex 自己压成 `.jsonl.zst`（本机 428 个里 370 个），续写时又解压回 `.jsonl`；两者并存时取 `.jsonl`。续写文件 `<thread>_<uuid>` 单独成会话、原会话记为父。
- 旧版 Codex（本机 254 个文件）没有 `token_usage_record`，退回 `token_count.total_token_usage` 相邻差值。
- **改了解析口径必须升 `SCHEMA_VERSION`**（当前 v4），否则旧库不重建，新旧数字混在一起。
- 成本：有 `cost-state` 真值的父会话，`All` 口径下不再叠加子代理估算（真值已含子代理）。定价表是 LiteLLM 2026-11-05 快照，未知模型返回 None 并在 UI 标注。
- **ChatGPT 桌面版内置的 Codex 也写 `~/.codex/sessions`**（进程在 `/Applications/ChatGPT.app/Contents/Frameworks/Codex Framework.framework`），格式与 CLI 相同，Codex provider 直接覆盖。2026-11 起多了几种记录：`response_item:agent_message`（多代理之间的消息，带 author / recipient）、`event_msg:item_completed`、`world_state`、`inter_agent_communication_metadata`，目前计数不入库。
- 「数据不同步」的根因曾经是 app 只读已有索引库、从不自己扫描（v0.1.2 及以前要手动 `agenthome scan`）。现在由 `crates/app/src/sync.rs` 负责：启动扫描 + notify 监听 + 每小时兜底。
- Claude Code 默认 30 天清理会话原件（`cleanupPeriodDays`），这是做 raw 层拷贝的根本原因；Desktop 发起的会话默认不清理。
- raw 层体积：Claude jsonl 里夹着大量 base64 图片，zstd 3 级只压到约 1/3（7.15 GB → 2.1 GB），不是想当然的 1/10。Codex 原件本来就是 `.zst`，raw 层先解压再统一压缩，内容 3.2 GB → 1.5 GB。
- raw 层追加用「多帧 zstd」：新增字节压成一个新帧接在版本文件末尾，`zstd -dc` 解压即拼接，不必重写整份。判断能不能接要重算已归档前缀的 sha256（sha256 状态无法从摘要恢复），所以变化的原件每次整读一遍，与 index 层整文件重解析同量级。
- raw 层不能用 index 的「size + mtime 未变」跳过：老用户的库早已入库，原件却从没拷过。归档要在 index 的跳过判断之前、按 raw 自己的清单判断。
- 主机名会变（macOS 连不同网络时 `.local` 名字会改），machineId 第一次取主机名后固定写进 `raw/machine-id`，否则同一台机器的归档会分裂成两个目录。

## 3. 额度与凭据

- Claude 订阅额度唯一合规的本地来源是 statusline 推给脚本的 JSON（`docs/06-statusline-安装.md`），**不要调用未公开的 OAuth usage 端点**，Anthropic 明文禁止第三方使用订阅 OAuth token（已拍板 v0 不做）。
- Codex 额度从最新 rollout 文件的 `event_msg.token_count.rate_limits` 读，零网络零风险；快照只在 Codex 有活动时更新，UI 要显示「多久前」。
- Claude statusline 的安装 / 卸载走 `crates/core/src/statusline_setup.rs`（CLI `agenthome statusline`、设置页按钮），原命令通过 `AGENTHOME_ORIG_STATUSLINE` 环境变量前缀保留；装卸前都备份 `settings.json`，看不懂的配置一律拒绝。**开发时不要在本机真实 settings.json 上跑 install**，测试用临时目录。
- **桌面版用户的 Claude 额度走官方 `/usage` 读屏**（`crates/core/src/signals/claude_usage.rs`，portable-pty + vt100）。坑：
  - 启动画面写「API Usage Billing」不代表没有订阅额度，`/usage` 面板里照样有周窗口；额度是异步加载的，比面板晚几秒出现，要等「% used」出现且画面稳定 1.5 秒再读，等 8 秒的探测会误判。
  - 新目录第一次运行会弹「是否信任此文件夹」，**不要自动确认**（测试时误确认过一次 `~/AgentHome`）；代码里遇到就报错退出。
  - 干净环境下官方 CLI 会把这次 `/usage` 存成一个会话 jsonl；设 `CLAUDE_CODE_CHILD_SESSION=1`（未公开）可关闭，`--no-session-persistence` 只对 `--print` 有效。刷新后检查项目目录有无新文件，有就报错。
  - **官方 CLI 每次启动都会按 `cleanupPeriodDays`（默认 30 天）删旧会话原件**。2026-11-08 一下子删了 284 个（08-19 ~ 09-14），内容只剩索引里的副本。后台启动时用 `--settings '{"cleanupPeriodDays":36500}'` 只对这次覆盖。
  - 从调用方继承的 `ANTHROPIC_BASE_URL`、`CLAUDE_CODE_*` 会改变 CLI 行为（例如在 Claude 会话里跑测试时走 API 计费），启动前 `env_clear`。
- **statusline 只在终端交互界面里被调用**：Claude 桌面版（Code 标签页）与 SDK 会话不渲染状态栏，装了包装脚本也永远收不到 JSON。Claude 会话 jsonl 里也没有额度字段，所以只用桌面版的用户只能偶尔在终端里跑一次 `claude` 拿快照。
- 本机没有 Claude statusline 文件时，栖息地按 hp=100 喂，否则住户会永远「休息中」；住户行显示「未接入额度」。

## 4. 设计与素材（生图）

- 生图要透明底时，让模型画在纯品红 `#FF00FF` 上再色键抠图；**仍需逐张检查**：有的返回了真透明 RGBA（直接用 alpha），有的把背景画成了黑色（必须重出）。处理脚本按「有 alpha 就用 alpha，否则色键」分支。
- 多状态精灵保持一致的办法：先出一张定风格，后续每张都同时传「角色头像 + 同状态的另一角色精灵」两张参考图。
- 吉祥物配色要和各家图标同色系，用户才认得：Claude 赭陶狐狸、Codex 黑白企鹅（OpenAI 黑白）、Gemini 蓝紫渐变猫。
- 背景色先让模型画近似值，再用 Pillow 把接近 `#0F1423` 的像素归一，否则和界面底色有接缝。
- Playwright 不允许 `file:` 协议，渲染设计稿时在 `docs/design/` 下起 `python3 -m http.server 18765`。
- 设计画布（Claude Design 画布）的交互子组件在本地 HTML 里跑不起来，本地副本把 `<dc-import name="Habitat">` 换成 `composed-*.png` 静态合成图再截图。

## 5. 验证与工具

- 截图前用 `script/bundle-dev.sh` 包成 .app 并 `open` 启动（裸二进制无 bundle id，截图工具找不到窗口；nohup 拉起的窗口不活动、不重绘）。
- 屏幕锁定时拿不到任何截图。
- 并行 subagent 同时改 core 和 app 时，core 用 `CARGO_TARGET_DIR=target/core`，避免抢 cargo 锁；core 改了公开类型（如给 `DailyUsage` 加字段）会让 app 的 mock 编不过，集成时补字段。
- notify 8 在 macOS 用 FSEvents，递归监听 `~/.claude/projects` 与 `~/.codex/sessions`；只认 `.jsonl` / `.jsonl.zst`，否则锁文件、sqlite-wal 的变化会让同步空转。监听报错时退回一次全量扫描。
- 同步线程持有自己的 `Store` 连接写库，UI 的 `SqliteDataSource` 另开连接只读；WAL 下互不阻塞，但 CLI `scan` 与 app 同时写时靠 `busy_timeout` 等待。
- 让 subagent 写 gpui 代码时，必须在 brief 里给出 `_ref/gpui-kit` 路径并要求先 grep 签名，否则容易臆造 API。
- 窗口在别的 Space（用户在全屏应用里）时，后台截图仍是最新的、点击能送达，但**文字输入送不进 gpui 的 Input**（只改了无障碍值），需要输入的验证只能等用户回到普通桌面或请求全屏控制。
