# 栖息地状态系统（Habitat）

> 2026-11-05。左栏 / 仪表盘 / 菜单栏里那间小屋不是装饰，它是三位住户（agent）的实时状态面板：谁在干活、谁在想、谁快没电、谁在等重置，一眼看出来。本文定义状态机、触发条件、动画与素材；设计稿的交互版在画布的「栖息地组件」画板（点 Play 看演示剧本）。

## 1. 住户与配色（对齐各家 App 图标）

| 住户 | 形象 | 色系 | 依据 |
|---|---|---|---|
| Claude | 狐狸，红棕帽衫 | 赭陶 #E8824F | Anthropic / Claude 图标的 clay 色 |
| Codex | 企鹅，黑色耳机 | 黑白 #E8ECF5 / #15171C | OpenAI / ChatGPT 的黑白标识 |
| Gemini | 猫，圆眼镜 | 蓝 → 紫渐变 #4285F4 → #9B72CB，耳内粉 | Gemini 星形标志的渐变 |

未来新增住户照此规则：先看它的 App 图标主色，再选一种能用该色自然表现的动物。

## 2. 住户状态机

| 状态 | 含义 | 触发（数据层） | 退出 | 动画 |
|---|---|---|---|---|
| `working` 工作中 | 有进行中的会话，正在产出 | 该来源 30 秒内有新 assistant / tool 记录追加 | 30 秒无新记录 → thinking 或 idle | 打字抖动：Y 轴 2.5% 两帧步进，0.42s |
| `thinking` 思考中 | 等模型 / 等工具返回 | 最近一条记录是 thinking 块，或 tool_call 已发出未见 tool_result | 收到新记录 → working | 左右轻摇 ±1.5°，2.2s |
| `happy` 完成了 | 刚完成一件事 | 会话结束（SessionEnd / 文件 10 分钟无写入且最后一条是 assistant 文本）、或工具调用成功且该轮结束 | 3 秒后回到 idle 状态 | 上下跳 7%，0.55s 往返，头顶星光闪 |
| `tired` 快没电 | 额度告急 | 任一窗口剩余 < 20% | 剩余 ≥ 20% | 下沉 2% + 微倾，2.8s；整体去饱和 |
| `sleeping` 休息中 | 没额度或没事干 | 窗口剩余 = 0（等重置），或该来源 10 分钟无活动 | 新活动 → working；重置 → happy 3 秒再 idle | 呼吸缩放 3.5%，3.4s；飘 z |
| `away` 外出 | 来源未接入 / 未检测到 | Provider.detect() 为假，或用户在设置里关闭 | 接入后 → sleeping | 不显示精灵，桌上立「外出」牌 |

优先级（同时满足时）：`away` > `sleeping`（额度 0）> `tired` > `happy` > `working` > `thinking` > `sleeping`（空闲）。

idle 状态 = `sleeping`（空闲）或 `thinking`（有会话但没动静），由上表最后两行决定。

## 3. 场景状态

| 维度 | 取值 | 规则 |
|---|---|---|
| 时段 | day / evening / night | 本机时钟：07–17 day，17–20 evening，其余 night。三张背景交叉淡入 1.2s |
| 壁炉与灯 | 亮 / 灭 | evening / night 亮；壁炉 0.9s 三帧闪烁，灯 3.2s 呼吸 |
| 星星 | 有 / 无 | night 时窗外四颗星错相闪烁 |
| 事件气泡 toast | 文本 | 来自数据层事件，2.4s 上浮淡出：工具开始 / 失败、会话完成（带成本）、窗口重置、额度告急、原件即将被清理 |
| 标签 | 显示 / 隐藏 | hero 尺寸显示「名字 · 状态 · 五格体力 · 百分比」，compact 尺寸隐藏 |

## 5. 素材清单（`docs/design/assets/habitat/`）

- 原图 `raw-*.png`：生图模型输出（品红底或透明底）。
- `processed/bg-{night,evening,day}.png` 1400 × 700，底色归一为 #0F1423。
- `processed/{claude,codex,gemini}-{working,thinking,sleeping,tired,happy}.png`：透明 PNG，高 320。
- `processed/composed-{night,evening,day}.png`：静态合成，给不能跑脚本的地方（README、飞书）用。
- 头像 `assets/processed/avatar-*.png` 256 × 256。

生成方式：先出一张完整场景定风格 → `edit_image` 以它为参考出三时段空场景 → 以头像 + 已有精灵为参考逐状态出图（品红底）→ Pillow 色键抠图 / 直接取 alpha → 裁切到内容 → 按高 320 缩放。新住户或新状态照此流程 5 到 10 分钟一套。

## 6. 在 gpui-kit 里怎么做

- 场景是一个 `Entity<HabitatState>`：`tod`、三个 `Resident { state, hp, since }`、`toast: Option<(String, Instant)>`。
- 数据层（core）发事件到 app：`SourceActivity { provider, kind: NewMessage | ToolStart | ToolDone | SessionEnd }`、`QuotaUpdated { provider, windows }`、`SourceDetected`。app 里一个 reducer 按第 2 节表格推状态，`cx.notify()`。
- 渲染：`img()` 叠在背景 `img()` 上，用 `absolute()` 定位；动画用 gpui 的 `Animation` + `with_animation`（`ease_in_out`、`steps`）做位移 / 缩放；时段切换用 opacity 过渡。
- 精灵换图只换 `ImageSource`，五张图一次性预加载进 `AssetSource`。
- 定时：`cx.spawn` + `Timer::after` 做 30 秒 / 10 分钟的状态回落；`happy` 的 3 秒也在这里。
- 可访问性：每个精灵给 `aria` 文本「Claude 工作中 58%」；`prefers-reduced-motion` 时关动画只换图。
