# 构建与发布流程（macOS）

> 2026-11-08 定稿。按本文从上到下做一遍即可发一个公证过的版本。每一步后面的「坑」都是真实踩过的，原因写清楚了，别跳过。
> 脚本：`script/release-macos.sh`。历史版本：v0.1.0、v0.1.1（未公证）、v0.1.2 起均已公证（最新 v0.2.2）。签名身份写在本地 `script/release.env`（不进仓库，模板 `script/release.env.example`）。

## 0. 前置条件（一次性）

| 项 | 要求 | 怎么确认 |
|---|---|---|
| Rust | 由 `rust-toolchain.toml` 钉为 **1.99.1**；需要 rustfmt 组件 | 在仓库目录 `cargo --version` 应显示 1.99.1 |
| 签名证书 | 钥匙串里有一张 `Developer ID Application` 证书，名字写进 `script/release.env` 的 `CODESIGN_IDENTITY` | `security find-identity -v -p codesigning` |
| 公证密钥 | App Store Connect API 密钥文件 `~/.appstoreconnect/private_keys/AuthKey_<KEY_ID>.p8` | `ASC_KEY_ID` / `ASC_ISSUER` 写进 `script/release.env`（模板 `script/release.env.example`，本体被 .gitignore 忽略）；脚本检查文件存在 |
| GitHub | `gh` 已登录有仓库写权限的账号 | `gh auth status` |

坑：
- **本机默认 stable 是 1.96，编不过 gpui-pre 0.3.11**（用了 1.97 才稳定的 `Option::map_or_default`）。不要改全局默认，项目里的 `rust-toolchain.toml` 已经处理。新装 1.99.1 后要 `rustup component add rustfmt --toolchain 1.99.1`。
- **公证不要走 Apple ID 密码。** Xcode 里登录的账号会话是 Xcode 私有的，`notarytool` 借不到。`notarytool store-credentials` 要的是 app 专用密码而不是登录密码，填登录密码会一直 401。正确做法是用上面那把 API 密钥（`--key / --key-id / --issuer`），无需交互、无需存 profile。凭据来源可以去看 `~/code_hub/habitly/desktop/scripts/release.sh`。
- 在本机大范围搜索 `.p8` / 钥匙串会被权限策略拦成「凭据探查」。需要凭据时先看其它项目的发布脚本里引用了什么，再按路径使用。

## 1. 发版前检查

```bash
cargo fmt --all --check
```

```bash
cargo clippy --workspace --all-targets
```

```bash
cargo test --workspace
```

三项都必须干净（2026-11-09 约 130 个测试；另有 3 个 `#[ignore]` 的真实数据基准，发版前用 `REAL_DB=<库副本> REAL_SRC=<一个大 jsonl> cargo test --release -p agenthome-core -- --ignored` 跑一次）。然后用真实数据做一遍端到端（见第 6 节的清单）。

## 2. 升版本号

只改根 `Cargo.toml` 的 `[workspace.package] version`，三个 crate 共用。提交信息写清楚这一版改了什么。

坑：
- **不要移动已发布的 tag、不要 force-push tag。** 发完发现问题就升一个补丁号重发（0.1.0 → 0.1.1 就是这么来的）。`git tag -f` + `git push -f` 会被权限策略判为破坏性操作拦下，而且会让已下载的人对不上版本。

## 3. 构建、签名、公证

```bash
./script/release-macos.sh 0.1.2
```

脚本做的事：

1. `cargo build --release -p agenthome-app -p agenthome-cli`（首次约 1.5 分钟，GPUI 全源码编译）
2. 组装 `dist/AgentHome.app`：二进制、随包 CLI `Contents/MacOS/agenthome`、`LICENSE` / `NOTICE` / `THIRD_PARTY_LICENSES.md`（放 `Contents/Resources/`）、由 `docs/design/logo/app-icon.png`（1024，已留 macOS 图标边距、圆角外透明）生成的 icns、Info.plist（bundle id `cn.peterchen.agenthome`，最低 macOS 15）
3. Developer ID 签名，hardened runtime，带时间戳；先签内层 CLI 再签外层 .app
4. `ditto` 打 zip
5. `notarytool submit --wait --output-format json`，**按返回的 status 判定**，不是 Accepted 就拉公证日志并失败；通过后 `stapler staple`、`stapler validate`、`spctl` 评估，再重新打 zip
6. 生成 `.sha256`（只写文件名）

产物：`dist/AgentHome-<版本>-macos-arm64.zip` 与 `.zip.sha256`。

环境变量：`CODESIGN_IDENTITY`、`ASC_KEY_ID`、`ASC_ISSUER`、`ASC_KEY_PATH` 可覆盖默认值；`NOTARY_PROFILE` 是 API 密钥不可用时的备选；`SKIP_NOTARIZE=1` 跳过公证。

坑：
- **签名后、公证前 `spctl` 报 rejected / Unnotarized Developer ID 是预期的**，脚本会打印说明继续往下走。公证后同一条命令应变成 `accepted · Notarized Developer ID`。
- **`notarytool --wait` 在 Invalid 时退出码也可能是 0**，只看退出码会把没过公证的包发出去。脚本已按 JSON 里的 `status` 判断。
- **bash 里中文全角括号紧跟变量名会被当成变量名的一部分。** `echo "签名（$IDENTITY）"` 在 `set -u` 下报 `IDENTITY�: unbound variable`。中文标点前后的变量一律写成 `${IDENTITY}`。
- **校验和文件里不要带目录。** 早期版本写成 `dist/AgentHome-….zip`，下载者在同一目录 `shasum -c` 会失败。

## 4. 发布到 GitHub Release

发布说明从上一版的线上说明派生，改版本号与「相对上一版」那一行：

```bash
gh release view v0.1.1 --json body --jq .body > notes-src.md
```

确认生成的说明文件**存在且非空**后再创建：

```bash
gh release create v0.1.2 dist/AgentHome-0.1.2-macos-arm64.zip dist/AgentHome-0.1.2-macos-arm64.zip.sha256 --title "AgentHome 0.1.2" --notes-file notes.md --target main
```

已发布版本只需替换资产时用 `gh release upload <tag> <文件> --clobber`。

坑：
- **`gh release edit --notes-file` 指向不存在或空的文件会把线上说明清空。** v0.1.2 就被清空过一次：临时文件放在 `/tmp`，几天后被系统清掉，命令链里 `sed` 失败了，后面用 `;` 连着的 `gh release edit` 照样执行。说明文件放在会话 scratchpad，命令之间用 `&&`，执行前 `test -s notes.md`。
- 发布说明里「是否公证」那一行要和包的实际状态一致。
- **发版前后的命令链一律用 `&&`。** 2026-11-10 一次 `cargo fmt --check && clippy ...; cargo test ...; git commit && git push`：格式检查失败后 clippy 被跳过，但 `;` 后面的测试、提交、推送照样执行，把没格式化、测试失败的提交推了上去。

## 5. 发布后验证（必须做）

从 GitHub 把刚上传的包下载回来，而不是验本地 `dist/`：

```bash
gh release download v0.1.2 -R PeterChen1997/agenthome -p "AgentHome-0.1.2-macos-arm64.zip*"
```

```bash
shasum -a 256 -c AgentHome-0.1.2-macos-arm64.zip.sha256
```

解压后给 .app 加上浏览器下载会带的隔离属性，再让 Gatekeeper 评估：

```bash
xattr -w com.apple.quarantine "0081;$(printf %x $(date +%s));Safari;" AgentHome.app && spctl --assess --type execute --verbose=2 AgentHome.app && xcrun stapler validate AgentHome.app
```

期望：`accepted`、`source=Notarized Developer ID`、`The validate action worked!`。

最后 `open AgentHome.app` 冒烟一次，三个页面都点一下。

## 6. 端到端验证清单（发版前与改动后通用）

CLI（真实数据，`~/AgentHome/index/agenthome.db`）：

| 命令 | 期望 |
|---|---|
| `agenthome scan` | Claude、Codex、Gemini 三个来源都扫到，失败 0、警告 0；增量重扫 1 秒左右 |
| `agenthome sessions --limit 5` | 最新会话在前，标题、项目、消息数合理 |
| `agenthome show <native id 前缀>` | 元信息与消息正文 |
| `agenthome stats --period month` | 汇总、按模型、按项目三张表，input 与 cache_read 量级合理（input 远小于 cache_read） |
| `agenthome quota` | Codex 有 rollout 快照；Claude 有 /usage 快照（`--refresh-claude` 立即读一次） |
| `agenthome activity` | 两个来源都「检测到」 |

App（截图逐页核对；锁屏或人不在时用 `--features capture` 离屏截图，见 `docs/09` §5）：左栏三项导航可切换；归档列表按日分组、打开大会话、中文搜索有结果；仪表盘各卡片出数；栖息地在左栏与仪表盘都绘制；`--appearance light` 与 `dark` 各看一次。

坑：
- **截图前用 `script/bundle-dev.sh` 包成 .app 再 `open` 启动。** 直接跑裸二进制没有 bundle id，截图工具找不到窗口；用 `nohup` 从脚本拉起时窗口不是活动窗口，第一帧之后不再重绘（列表一直转圈，点一下窗口才出来）。
- **屏幕锁定时 macOS 不给任何截图**，看起来像 app 坏了，其实只是拿不到图。先确认 `CGSSessionScreenIsLocked`。
- 测试明暗主题不要去改系统外观（需要额外授权且影响用户），用 `--appearance light|dark`。
- 改了 core 的解析口径**不要升 `SCHEMA_VERSION`**：重建会让原件已被 agent 清理的会话永久消失。用 `store.rs` 里的一次性迁移（`meta` 表记完成标记，参照 `fix_injected_codex_titles`、`reprice_if_needed`）修老数据；价表变了打开库时自动重算成本。
