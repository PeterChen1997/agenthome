验证：`cargo fmt --check` 干净，`cargo clippy --workspace --all-targets` 零警告，`cargo test --workspace` 48 个全绿；真实库（2,808 会话 / 353,505 消息）启动无 panic、stderr 为空。

**视觉核对（解锁后截图逐页核对，真实库）**：归档列表按日分组、项目计数、子代理折叠、进行中标签正常；打开 555 条消息的会话，轮次编号、Trace 折叠行、轮次导航条正常；中文搜索"控制平面"命中 3 个会话；仪表盘住户卡、累计 token、到期列表、趋势、今天、按模型 / 项目、归档健康全部出数；栖息地在两处都正确绘制（当前时段傍晚，壁炉亮，两位住户因 10 分钟无活动为休息中，Gemini 外出）。

核对中发现并已修复：Codex 的 input 含缓存导致"输入"虚高两个数量级（入库前改为减去缓存读，schema 升到 v3 重建）；额度来源标签显示整条文件路径（改为"rollout 快照 / statusline"）；超过一天的倒计时显示成 143 小时（改为 5d 23h）；栖息地 hero 标签挤在一行互相覆盖（改为居中于各自桌位、缩小、去掉百分比）；缩小版的"N 位在线"说明字太大挡住住户（缩小移到左上）。另：用脚本 `nohup` 直接拉起二进制时，窗口不是活动窗口，第一帧之后不再重绘（后台查询其实已完成，点一下窗口立即出现）；用 Finder / `open AgentHome.app` 启动则正常。属脚本启动的边角情况，记录待查。

## 已知偏差与待办

> 2026-11-08：以下条目已全部并入 `docs/10-设计落地清单.md`（含证据与批次），之后以那份清单为准，本节不再更新。

来自 C / D 报告，代码内均有 TODO：

- `SessionSummary` 无成本字段：列表用第一个模型估算，详情按消息估算；应在 core 给 `SessionSummary` 加 `cost_usd`（估算优先真值）。
- 子代理折叠靠「同目录同时间区间」启发；应用 `parent_session_id`。
- 「仅归档 / N 天后清理」每会话标签与视图筛选需要 core 暴露原件状态；现只在归档健康里有计数。
- 「在 Finder 显示」禁用：`DataSource` 未暴露原件路径。
- Trace 行状态只有 OK / ERR；EXIT N、+a −b 需 core 解析工具输出。
- 星标仅内存；设置页占位；assistant 耗时用相邻消息间隔近似。
- 仪表盘：趋势第三档是消息数而非会话数；按住户未再按模型分段；「进行中」无会话标题；无订阅续期行；趋势柱无悬停。
- 栖息地：gpui 无旋转 / 单轴缩放 / 滤镜，thinking 用左右平移、tired 用降 opacity 代替；无额度文件时按 hp=100 喂（否则永远休息中）。
- 菜单栏弹窗未做（gpui tray 可行性待查）。
- 文件监听（notify）与 raw 层拷贝仍未做，仍需手动 `agenthome scan`。
